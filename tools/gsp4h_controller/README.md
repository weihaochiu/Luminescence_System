# GSP-4H 獨立光源控制程式

此工具獨立啟動，只控制 GSP-4H 光源。沒有匯入或啟動主程式，不更動
Recipe、相機、SMU、Relay、EL 或 PL 拍攝流程。

## 啟動

雙擊同資料夾的 `run_gsp4h_controller.bat`。

啟動檔優先使用專案根目錄 `.venv`，找不到時使用 Windows Python launcher。
獨立程式只需要 `requirements.txt` 的 PySide6（含 QtSerialPort），沒有使用
pyserial、VISA 或主程式的設備模組。

也可在本資料夾執行 `python main.py`，或在 repository 根目錄執行：

```powershell
python -m tools.gsp4h_controller.main
```

若尚未安裝依賴，使用所選 Python 執行：

```powershell
python -m pip install -r requirements.txt
```

## 啟動自動掃描與連線

- 列舉 Windows 可用 COM PORT，包括主機 RS232、USB 轉 RS232，以及其他串口。
- 顯示系統可取得的 description、manufacturer、USB VID/PID 與轉接器序號。
- 預設 19200 bps、8 資料位、1 停止位、無同位檢查、無流量控制。
  說明書沒有列出同位檢查／流量控制；若連線失敗，可人工選擇偶數／奇數同位檢查後重掃。
- 依序探測，COM6 優先。掃描只發送 `T#`、`SA#`、`SB#`、`SC#`、`SD#`。
  必須模式有效、四個通道回覆正確且亮度都在 0～255，才列為相容候選。
- COM6 相容時自動連接 COM6；否則只有一個相容候選時自動連接；
  有多個其他候選時要求人工選定；沒有候選時維持未連線。
- 每個探測串口都會釋放，最後重新開啟選定串口並讀取全部設定。
- **啟動、探測與連線不送出模式設定、亮度設定或點燈命令。**
  如果設備原本就在發光，程式也不會在啟動時改變它。
- 文件沒有設備型號或唯一設備 ID 查詢。協定驗證不能保證設備就是 GSP-4H；
  USB 序號辨識的是轉接器，不是轉接器另一端的光源控制器。

## 使用

1. 確認連線 PORT 與設備讀回值。
2. 拖動滑桿或修改數字就直接調整亮度，沒有「套用」按鈕。
   拖動時約每 80 ms 提交一筆；通訊忙碌時，每通道只保留最新要求值，
   不會把所有拖動中間值排成長佇列。
3. 寫入後讀回該通道並查詢模式。亮度和開關獨立：開燈時直接改變亮度；
   關燈時調整亮度仍保持常暗，非零值不會自動點燈，歸零也不會自行改變全機模式。
4. 只有一顆光源開關按鈕：常暗 L 顯示「開啟光源」，常亮 H 顯示「關閉光源」。
   開燈會先確認常暗，再套用並逐一驗證四通道的設定，最後切常亮並重新讀回。
   其中一筆失敗時不繼續開燈，並嘗試恢復常暗。
5. 「關閉光源」只切換常暗並讀回，保留各 CH 的亮度。
   操作途中可取消開啟並關燈；狀態未知時按鈕顯示「重試關燈」，不允許直接開燈。
6. 「讀取設備設定」重新讀取全機模式與四通道亮度；畫面中的讀回值是
   最近一次成功查詢的設定值，不是連續量測的光強。
7. 可匯出最近 1500 行通訊紀錄，包含時間、TX、原始 RX 與錯誤。

### 亮度設定與保存

- BAR／數字顯示使用者的「亮度設定」，旁邊的「設備讀回」顯示最近成功查詢的硬體設定。
  例如重啟後 BAR 保留 80，但硬體讀回為 0；按開啟光源才套用保存值，這不是讀回成功的假值。
- 四通道亮度保存至 Windows 使用者設定目錄下的 `Luminescence_GSP4H/brightness.json`。
  使用獨立設定檔，不共用主程式設定，也不將開燈狀態保存為自動啟動命令。
- 修改後自動保存，關燈或退出前立即保存最新要求值。寫入採暫存檔與原子替換；
  寫入失敗會明確顯示，不把先前存檔誤認為最新設定。
- 首次沒有保存值時，成功連線後以設備讀回初始化亮度；已有保存值時，
  連線、重新讀取、一般關燈及退出硬體歸零都不覆蓋保存值。
- 啟動／連線只讀取設備，不自動套用保存值或切常亮。設備原先已常亮時，如實顯示讀回狀態。
- 儲存失敗也會先執行硬體安全關燈，再保留視窗供修復儲存問題後重新退出。

### 連線燈號

- 灰燈：未連線。
- 黃燈：掃描、連線或讀回驗證中。
- 綠燈：已連線且模式與四通道設定成功讀回。
- 紅燈：連線、USB 或讀回異常；停止一般亮度設定，允許重試關燈。

燈號附文字標示；綠燈表示通訊已驗證，不代表實際光強或光源是否點亮。

### 目前模式與不亮原因

全機控制區以醒目文字顯示有效的設備模式讀回，與連線燈號分開：

- **常亮模式（H）**：綠色底。依各 CH 的讀回亮度判斷；亮度為 0 的通道不發光。
  四通道讀回皆為 0 時，另外明確提示「常亮模式已啟用，但四通道亮度皆為 0」。
- **常暗模式（L／常滅）**：黃色底。即使 CH 設定非零，這個模式也不持續點亮光源。
- **模式未確認**：灰色底。未連線、通訊異常或讀回失敗時，不把先前模式當成目前已確認狀態。

模式在連線、亮度調整、模式切換及「讀取設備設定」完成有效讀回後更新。
如果直接操作設備面板，按「讀取設備設定」重新確認；讀回不會覆蓋已保存的亮度設定。

0～255 是 PWM 設定等級，不是經過校正的光強或線性百分比。第一版沒有外部
觸發、頻閃時間、相機同步或 EL → PL 自動拍攝功能。

## 關燈、斷線與 USB 中斷

- 一般「關閉光源」只發送 `TL#` 並讀取模式與四通道確認，保留硬體及使用者亮度設定。
- 主動斷線與關閉視窗會保存亮度，再發送 `TL#`，依序將硬體 CH1～CH4 設為 0。
  這些硬體 0 不會寫回 BAR 或保存檔。
- 關燈／關閉先取消尚未送出的亮度更動；開燈途中會在各指令邊界檢查取消要求。
  已送出的有界指令完成後，優先執行關燈，不會再執行舊的開燈要求。
- 即使某個設定 acknowledgement 失敗，仍嘗試其他通道，最後讀取模式與四通道。
- 一般關燈須讀回 L 及四通道設定；斷線／退出則須讀回 **L + 四通道皆為 0**，且成功釋放串口。
- 若失敗，保留控制 session、取消退出，狀態顯示未確認，允許重試；
  不將逾時、錯誤字母或之前保存的數值當成成功。
- USB 拔除／串口 I/O 中斷時清除已知設定，停止一般點燈操作。
  不會自動恢復亮度、不會自動重新點燈，也不會自動換另一個 PORT 重試關燈。
- 恢復原連線後，按「重試關燈」或「關燈並斷線」。
  若原轉接器提供序號，重新開啟時必須符合原序號；無序號時只能核對原 COM 編號。
  Windows 若換了 COM 編號，原串口的關燈重試會失敗，需人工確認硬體已關閉。
- 不能從軟體設定讀回證明光源實際已熄滅。斷線、電源失效或強制終止程序時，
  軟體無法保證關燈；實機驗收仍需觀察光源。正常關閉必須走視窗的關燈流程。

## 文件協定

| 功能 | 指令 | 回覆 |
| --- | --- | --- |
| CH1 亮度 100 | `SA0100#` | A/a acknowledgement，之後 `SA#` 驗證 |
| CH2 讀取亮度 | `SB#` | 例如 `b0136` |
| 常亮／常滅 | `TH#` / `TL#` | H/h、L/l，之後 `T#` 驗證 |
| 讀取模式 | `T#` | H/h 或 L/l |

CH1～CH4 對應 A～D，亮度固定四位。發送 ASCII，不另加 CR/LF。
回覆依固定長度累積，支援分段收取及選配 CR/LF／尾端 `#`。
說明書有大小寫與 I/l 印刷歧義：接受對應字母的大小寫，**不把 I 當成已驗證的 L**。
逾時後先排空延遲資料，避免把舊的殘缺回覆當成下一筆查詢。

## 測試與實機驗收

在 repository 根目錄：

```powershell
python -m unittest discover -s tests -p test_gsp4h_controller.py -v
python -m unittest discover -s tests -v
```

自動測試使用模擬設備，不操作實際 COM PORT。驗證探測只有讀取命令、
候選選擇、指令／讀回、保留亮度的關燈、保存與恢復設定、開燈取消、USB 異常及背景執行緒退出。

實機驗收依序檢查：

1. 未連設備時可正常啟動與退出。
2. 連接設備或 USB-RS232 後，啟動自動找到 PORT；光源原狀態不被改寫。
3. 確認模式與四通道亮度讀回；選已接光源的通道從低亮度測試。
4. 常暗時拖動滑桿或修改數字，確認亮度讀回改變但沒有點燈；按開啟光源後依保存亮度發光。
5. 按關閉光源，確認熄滅且 BAR 數值不變；再次開燈恢復相同亮度。
6. 主動斷線／關閉視窗確認硬體熄滅與歸零；重啟確認保存值保留且未自動點亮。
7. 確認 USB 拔除後狀態未知、控制停用；恢復同一轉接器後重試關燈。

USB-RS232 必須已安裝其 Windows 驅動並呈現 COM PORT；本程式不安裝轉接器驅動。
USB 轉 TTL 串口的電氣介面不同，不能用來取代設備要求的 RS232。
